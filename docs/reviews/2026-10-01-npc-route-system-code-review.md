## 一、Critical（1，已修）

**C1｜抵达判据只兜水平、没兜 Y ⇒ 永久卡住且零日志** — `NpcRouteGoal.java`（原 `:128`）

- **机制**：移动层对**地面** NPC 的到位判定**只看水平**（`NpcEntity.tickMoveCommand` 的注释与实现都是
  `distSqr = dx*dx + dz*dz`，`:1270`），一进水平 1.0 格就清 `moveTarget`（`:1273-1276`）；
  而 route goal 原先要求 `|Δy| ≤ 2` 才前进 ⇒ 两者形成"那边每 tick 清、这边每 tick 补发"的死循环：
  **下标永不前进、终点表情永不播、且一条日志都没有**。
- **顺带推翻了一处注释**：goal 类注释声称"万一移动层到不了，它的有界失败会在约 5 秒后清掉目标 ⇒ 不会卡死" ——
  这条在 C1 这条路上**不成立**：有界失败在到位分支**之后**（`:1287`），而该分支已 `return`。
- **触发条件**：任一路点的 y 不可站立（数据层不校验 y）。现有两条路线的 y 恰好都能站 ⇒ 尚未触发。
- **修复**：抵达 = 水平在半径内 ∧（高度合适 **∨ 移动层已把目标放下**）；并在靠后半句兜底且 Y 差得多时
  按路点打一条 WARN（否则这类数据错误永远无声）。最后一个路点仍要求"真的停下"再算抵达（表情别滑行）。

## 八、已知限制与设计取舍（均经用户知情并接受，**不是缺陷**）

| 项 | 说明 |
|---|---|
| **CG 与路线的时序** | 服务端感知不到 CG（CG 是纯客户端演出、零服务端状态）⇒ **无法自动让位**，只能靠内容顺序；CG 相机轨迹触发即烘成世界坐标 ⇒ **"边走边演"不成立** |
| **`root` 是"走进区域"的近似** | 原版谓词**不能引用实体**（`LocationPredicate` 的全部字段都不含实体）⇒ 用"以末的站位为心、x/z 各 ±8"的方盒近似"看到末" |
| **`root` 触发时若附近没有末** | `MoEntranceTrigger` 的搜索半径 48 格内找不到末 ⇒ **登场 CG 不放**，只留一条英文 WARN（用户选定"不重试"✓ 该 WARN 已在实机日志里真实出现过一次）|
| **`2_0` 不区分"首次激活"与"重复右键"** | `default_block_use` 在石碑已激活后再右键同样会触发；对一次性进度无影响 |
| **路线上 `move` 指令无效** | 刻意（设计 D10）：goal 每 tick 会把 `moveTarget` 改回当前路点 |
| **`stop` 是终止、`attack` 不清路线** | 设计 D6/D7：`stop`/`reset` 清路线（重启不恢复）；攻击期间暂停、打完继续 |
| **被困住会一直重试** | 设计 D3：每约 5 秒一轮（goal 的补发会重置移动层的有界失败计数）|
| **`WARNED` 类集合只增不清** | 同项目既有先例（CG 的 `WARNED_UNKNOWN` 亦然），按坏名/坏路点计，量极小 |
| **表达式/名字不做校验** | 路线的 `end_emote` 与 `/beloong npc … play` 同口径：哪条动画存在是**资产**，名字对不上时客户端一条 WARN，不崩 |
