## 2. 架构速览（现在的形态）

**私有分身（private double）**：每个玩家一只自己的 NPC。可见性靠覆写 `Entity#broadcastToPlayer` → `NpcEntity#visibleTo`（纯函数）。
- `owner == null` = **公共锚点**：有剧情声明时**永不显示给任何人**（设计 D8；用户裁定）；**没有**剧情声明的公共 NPC（地黄龙等）恒可见。
- `owner == 我` = 我的分身：需已开始剧情且未进入"通关回收"态。

**交互闸门**（2026-10-14 修）：`NpcEntity#isTalkableBy(player)`
- 无主 ⇒ 只有**没有剧情声明**的可对话（有剧情声明的锚点**永不**）；
- 有主 ⇒ 只有主人可对话。
- ⚠️ 与 `visibleTo` **刻意不同**：调试视角（`/beloong npc debug`）只改"看得见"，**不改"能交互"**。
- 两条路径统一走它：`NpcDialogueHandler`（右键）+ `NpcDialogueReplyPayload`（回复包，改包客户端可凭实体 id 直接发）。

**对账器**（`npcstory/NpcStoryHandler`，每 100 tick 一次）——只剩两条清理：
| 判定 | 处置 |
|---|---|
| 重复分身 / 孤儿 / 通关回收 | **只删不撤** |
| **租约到期** | **删 + 撤整条链**（撤的唯一入口在 `removeDouble` 内）|
| 主人**离线**且到期 | **当场删** + 记入服务器级待撤回表（方案乙）⇒ 登录时消费撤回 |

**中心不变量**：**「撤回进度」与「删除分身」成对**。`revokeStory` 只有 1 处定义 + 2 处调用：
`removeDouble` 内（成对主路径）与 `revokeStoryFor` 包装内（离线已删、只撤不删）。
守卫 15.6-③ 把这两处钉死；**唯二例外**都带"再判"（离线路径 + 登录消费时再判"已开始 ∧ 未通关"）。

**租约 + 续约**（`lease.ticks`，缺省 72000 = 1 小时；`-1` = 永久）
- 续约：拿到**里程碑**时把租约重置为一整段，时长取自**该剧情自己的 `lease.ticks`**（`story.expiryAt(now)`，不硬编码）。
- 里程碑 = **剧情链上 `start` 与 `end` 之间**的进度（两端点不算）；缺省由 `chainBetween` 沿 `parent()` 推导
  ⇒ **从 `end` 的父开始走、遇到 `start` 收工**；走不通 ⇒ 空集（fail-closed）。
- `lease.renewal`（缺省 **true**，模组 `mo.json` 显式写）+ 可选 `lease.renew_advancements` 覆盖。
- ⚠️ **`lease.ticks` 下限 240**（<240 加载期直接拒绝并点名）：登场 CG 是 120 tick，低于它会"删+撤 → 重开场 → 重播 CG"死循环。

**序章**（`npcstory/NpcPrologueHandler`，每 20 tick）流程：
```
① 活着/非旁观/非骑乘 ② 必须在剧情声明的维度（否则什么都不做 = 剧情可暂停）
③ fail-closed（ROOT/ENTRANCE_DONE 的 holder 不存在 ⇒ continue，不生成不播 CG）
④ 已完整开场过（1_0 ∧ root 都在）⇒ 结束
⑤ 等客户端"就绪"信号（F1）；收不到则 delay + readyFallbackGraceSeconds 兜底 + WARN
⑥ 有 root 无 1_0 ⇒ 补授 1_0（先问 CgCompletionHandler.hasPending，CG 正在播就不补）
⑦ 清场：discard 属于该玩家该剧情的孤儿分身
⑧ 不在入场落点 ⇒ 传送（本 tick 结束）
⑨ faceNorth（正北 yaw 180）+ 确保分身（先分身**再**授予 root —— 顺序铁律）
⑩ 授予 root ⇒ 播 CG
```

**CG 与客户端同步**（2026-10-14 新增，三个载荷）
- `NpcClientReadyPayload`（C2S，无数据）：客户端在 `Minecraft#getOverlay() == null`（加载遮罩消失 —— **原版自己就用它**判断"能不能接受操作"）
  且连续 20 tick 后发一次 ⇒ 序章延迟**从收到它起算** ⇒ 修掉"屏幕还在加载地形、CG 已开播"。
- `CgStartedPayload`（S2C，CG 名 + 时长）：`CgAnimation` 在 `startCutsceneForPlayer` **之前**发 ⇒ 客户端**收到它的那一刻**才算真正起播，
  本地计时到点回 `CgFinishedPayload`（C2S）⇒ 服务端 `CgCompletionHandler.settleFromClient` 立刻结算。
  ⚠️ 服务端自己的计时**降级为兜底**（`cutsceneTime + 200`）⇒ 保住"只要 CG 开始过就一定拿到进度"。
- **F3 表情押后**：`CgCompletionHandler.holdEmote(npc, cutsceneTime + 200)` ⇒ 表情到期处理器先问 `ownsEmote(npc)`，
  是则跳过 ⇒ 修掉"动画播一半就停、而 CG 运镜还在"。刻意用**限时押后**而非"注册/注销配对"⇒ 不存在忘了解锁导致永不清理。

**性能（S1 / S2 / A1）**
- **S1 `npcstory/LoadedNpcIndex`**：`EntityJoinLevelEvent` 登记 + `EntityLeaveLevelEvent` 移除（**仅加速**）；
  **正确性靠读取时过滤 `isRemoved()`**（卸载路径打的就是这个标记）。⚠️ **join/leave 两个处理器都必须闸掉客户端**
  （`isClientSide`）—— 单机就是集成服务端，客户端线程会删掉服务端的条目（审查 C1）。
  ⚠️ join 处理器**零世界交互**（该事件 javadoc 警告会区块加载死锁）。A1 被它吞掉（一次遍历覆盖所有剧情）。
- **S2 `NpcDialogueStage.stateOf` 的短 TTL 缓存**（20 tick）：`isEarned`/`visible` 的共同收口。
  ⚠️ **写侧必须显式失效**：`NpcDialogueStage.invalidate(player)` —— 序章授予 / CG 授予 / **任意进度的 AdvancementEarnEvent**（这条覆盖数据包与命令授予的 `1_1`/`2_1`）/ 撤回，四处都要。
  `UNKNOWN` 不入缓存。

**方案乙（离线清理）**：`npcstory/PendingStoryRevoke`（主世界 `SavedData`，`Set<UUID>`）
- 离线且到期 ⇒ `PendingStoryRevoke.mark(server, uuid)` + `npc.discard()`（当场删，世界干净）
- 玩家登录 ⇒ 序章**在任何开场动作之前** `consume(...)` ⇒ 再判"已开始 ∧ 未通关" ⇒ `NpcStoryHandler.revokeStoryFor(...)`
- ⚠️ 为什么必须记一处状态：撤进度需要一个**在线** `ServerPlayer`；不记的话上线时只剩"有 root 却找不到分身"这一条判据，
  而"找不到"≠"不存在"（分身可能在没加载的区块里）⇒ 会误撤正常玩家（= 已删除的 D21 原罪）。
- ⚠️ 已知窗口：删除后、登录前**服务器崩溃且表未落盘** ⇒ 该玩家停在"有 root、无分身" ⇒ 管理员撤整条链一次即可。

## 9. 工作方式约定（本项目一贯）

- 流程：**先讨论 → 先设计 → 先计划 → 用户批准 → 才动代码**；改完必跑 `build` + 全套守卫。
- 文档/注释/提交信息**用中文**；**日志文案用英文**。
- 结论必须给 `文件:行号` 证据；**注释不许说假话**（本项目把过时注释当缺陷，我因此订正过多处）。
- 大改后**派独立审查**（只读），修掉 Critical 再继续。
- **永不推送**；jar 装机后 `mods` 里留 `.bak-*` 备份（当前 15 份，可清）。
- 守卫脚本在**仓库外** ⇒ 改它不占提交（有时我会用一个空提交留记录）。
