### 3.2 台账要解决的三个问题

1. **提取 NeoForge 源码到可检索目录**：解压 `neoforge-21.1.236-sources.jar` 到
   `build/review-src/neoforge-21.1.236/`，使各道子代理能用 `read`/`grep` 直接引用 `路径:行`。
2. **锁定版本 vs 参考源码版本对账**：
   - `build.gradle` 的 curse 坐标形如 `<slug>-<projectId>:<fileId>`，下载产物命名为
     `<slug>-<projectId>-<fileId>.jar`。按 **fileId 精确匹配**缓存 jar，逐个确认存在。
     （抽查已发现 `dragons-survival-420799` 缓存中存在 `...-8564714.jar` 而 `build.gradle`
     引用 `:8726322`；`geckolib-388172` 缓存中有 `...-7023453.jar` 而引用 `:8350073`
     ⇒ **必须逐个按 fileId 精确核对，不能取"第一个碰到的 jar"**。）
   - 参考源码树版本从各自 `.git` 取（`git describe --tags` / `git log -1 --date=short`），
     **不要**读其 `gradle.properties`：实测其 manifest 多为模板占位
     （如 Cataclysm 只有 `loaderVersion="${loader_version_range}"`），读不出真实版本。
3. **给出每个模组的取证等级**，三选一：

| 等级 | 含义 | 允许的结论强度 |
|---|---|---|
| **A 源码级** | 参考源码版本与锁定 jar 版本一致 | 可直接引 `源码路径:行` 作为证据 |
| **B javap 级** | 版本不一致或无源码 | 只能引 `javap -p -c` 打实际 jar 的输出 |
| **C 不可用** | jar 缺失且无源码 | 相关结论降级为"待确认"，不得定级 |

**产出**：`docs/reviews/` 报告内的"对照物台账"表 + 阶段 0 结束时的**基线冻结**
（`git diff c38c7ab..disaster2 > build/review-src/scope.patch`，防审查期间工作树变动）。

## 七、证据与分级规则

1. **双证强制**：涉及平台行为的结论必须同时给出
   a) 本项目证据 `文件:行`；b) 平台/第三方证据 `源码路径:行`。
   只有单侧证据的只能定为"**待确认**"，**不得**定级为 S1/S2。
2. **每条发现必须可复现**：附上产生该结论的命令或读取路径。
3. **正面确认单列**：已核验为正确、后续不必重复怀疑的部分单独成节（沿用 09-11 两份报告的
   "已核验为正确 / 非问题的部分"做法）。
4. **分级沿用本项目 house style**：**S1 阻断 / S2 严重 / S3 中等 / M 次要**
   （与 `2026-09-11-loong-palace-sky-code-review.md`、`2026-09-11-disaster-biome-removal-review.md` 一致）。
5. **不得以"没有测试套件"为由降低定级**：本项目无测试套件，验证靠编译 + 静态探针 + 实机；
   静态可判定的问题一律按静态证据定级。
