# 租约离线结算 + 提醒数据驱动 + npc_story 结构重组 设计文档

**日期**：2026-10-01
**状态**：**已批准**（对话中逐节确认）
**上游**：`2026-10-01-multiplayer-npc-design.md`（D1–D21）· `2026-10-01-mynpc-command-and-finish-reaping.md`
**本设计要解决的四件事**：

1. **离线不结算**：龙宫维度**常加载** ⇒ 私有分身即使主人离线也**一直 tick**，而对账器**只遍历在线玩家** ⇒ 到期的分身**永远不被判定** ⇒ 常加载维度里**无界累积**（用户的性能动机）
2. **提醒不可数据驱动**：租约到期 / 离开维度两个提醒的**提前量**与**文案**都不可配；文案里"龙宫"二字写死在语言文件里（上一轮审查给 D18 记的瑕疵）
3. **字段平铺**：`npc_story` 的 8 个字段目前平铺，租约相关与维度相关的字段散落
4. **校验有软着陆**：部分错误只打 WARN 然后按默认值继续跑 ⇒ 与"写错了而不知道"直接矛盾

---

## 一、决策（D1–D14，全部经用户逐条确认）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 离线巡检**只清分身**；进度留到**下次登录**由已有的 D21 分支撤回 | 离线读不到玩家进度（`PlayerAdvancements` 只存在于在线的 `ServerPlayer` 上）⇒ 不引入任何每玩家持久状态，最终状态与在线结算**逐字一致** |
| D2 | JSON 嵌层：`lease{}` / `dimension{}`；顶层只留 `start_advancement` / `end_advancement` / `spawn` / `cg` | "把租约放一起、把离开维度放一起" |
| D3 | 提醒文案：`warn_text`（字面，**优先**）> `warn_key`（翻译键）> 内置默认键 | 数据包作者想"一定能显示"就写字面文本；要多语言再写键 |
| D4 | `dimension.host`（**巡检扫哪**）+ `dimension.enforce`（**是否启用"离开就清"**，默认 **false**） | 一个字段原本要同时干两件事，而整合包恰好两边都要相反：**需要** host（否则 0 人在线时巡检无维度可扫 ⇒ 离线清理失效），**不能要** enforce（玩家会为变龙长期离开龙宫） |
| D5 | 缺省：`lease.ticks = 72000`（1 小时，**不变**）· `dimension.grace_ticks = 6000`（**5 分钟**，由 1200 改）· 两个 `warn_before_ticks = 600`（30 秒） | 用户裁定："流程不长，很快就能完成" |
| D6 | **`keep_after_finish: true` 的剧情不参与离线清理** | 离线判不出"他是否已通关"，而 `true` 的全部意义正是"通关后永久保留"（我们短剧情的 D6）⇒ **宁可不清理，也不误删** |
| D7 | 未知名拒绝**递归化**（逐层）；命中**旧版写法**时 ERROR 里附**迁移提示** | 直接解决"旧版写法忘了更新" |
| D8 | **报错不静默**：凡是服务端查得到的，一律**加载期硬校验 ⇒ 拒绝整文件** | 用户原则："跑起来了但行为不对"比"压根没跑起来"更难查 |
| D9 | `cg` 名不存在 ⇒ 加载期 **ERROR 但不拒绝**（剧情照常加载，只是不播 CG） | 保住 D12 的既定取舍：坏 CG 数据不该毁剧情 |
| D10 | `warn_key` 指向的语言键**是否存在无法校验**（`lang` 是客户端资源）⇒ 靠"玩家屏幕上出现原始键名"暴露 | 物理限制，必须写进文档 |
| D11 | 全局配置 `Config.NpcStory.expiryWarningTicks` **保留为兜底**（某条剧情没写 `warn_before_ticks` 时用它）；`reconcileIntervalTicks` / `enabled` 不动 | 服主仍能一处调全部 |
| D12 | 离线清理的日志 reason 用 **`timeout_offline`**（与在线的 `timeout` 区分） | 从日志就能分辨是哪条路径干的 |
| D13 | 实现上：`NpcStoryLoader` 通过 `AddReloadListenerEvent.getRegistryAccess()` 拿到 registry access（`INSTANCE` 不变，每次 reload 重新绑定） | 让 `host` 能在**加载期**校验（维度注册表在 reload 时已完整） |
| D14 | 迁移**同批**完成：代码 + 模组自带 `mo.json` + 整合包 `mo.json` | 旧结构会被拒绝 ⇒ 分批会出现"数据被拒 + 分身根本不生成"的中间态 |

## 二、架构：三条路径各管一段

```
① 事件路径（生成 + 演出）                    不动
② 巡检路径（每 reconcileIntervalTicks，默认 100 tick = 5 秒）
     ├─ owner 在线  → 走**完整判定表**（与现状逐字相同）
     └─ owner 离线  → **只判租约到期** ⇒ 只删分身（reason=timeout_offline，不撤进度）
③ 登录路径（进服那一刻）                    不动 ⇒ 已开始 ∧ 无分身 ⇒ D21 撤回整条链
```

**改动点只有一处**：把"只遍历在线玩家"改成"**也遍历 owner 表里不在线的人**" ——
而那张 `owner → 分身` 表**本来就已经建好了**（`reconcileStory` 遍历维度全部实体时，离线玩家的分身早就在里面）。

**离线路径为什么只判一件事**：

| 规则 | 离线为何不判 |
|---|---|
| 维度（离开就清） | 需要玩家**此刻在哪** ✗ |
| 孤儿（未开始却有分身） | 需要**进度** ✗ |
| 通关回收 | 需要**进度** ✗ |
| 重复分身 | 能判，但 tie-break 要用玩家坐标 ✗ ⇒ 留给登录 |

⇒ 这四项**全部在登录那一刻由已有的判定表补做**，最终状态与在线结算逐字一致。

**离线巡检扫哪个维度**：`dimension.host` 有值 ⇒ **只扫它**（无论有没有人在线 —— 这是离线清理能工作的关键）；
无 `host` ⇒ 沿用旧行为（扫在线玩家所在维度）⇒ **0 人在线时不扫 ⇒ 该剧情的离线清理不生效**（文档必须写明）。

## 三、数据结构（`npc_story` 全貌）

```jsonc
{
  "_comment": "…（放行；未知名仍然被拒绝，校验改为**递归**）",

  "start_advancement": "beloong:npc/root",
  "end_advancement":   "beloong:npc/5_1",
  "spawn": "anchor",
  "cg": "mo_entrance",

  "lease": {
    "ticks": 72000,                  // 缺省 72000（1 小时）；-1 = 永久（⇒ 离线清理失效）
    "clear_on_logout": false,        // 缺省 false
    "keep_after_finish": false,      // 缺省 false（通关即回收分身）
    "warn_before_ticks": 600,        // 缺省 600（30 秒）；0 = 不提醒
    "warn_text": "…",                // 可选：字面文本（优先）
    "warn_key": "…"                  // 可选：翻译键（次之）；都没有 ⇒ 内置默认键
  },

  "dimension": {
    "host": "beloong:loong_palace",  // 剧情所在维度 ⇒ 巡检扫这里；省略 ⇒ 退化为扫在线玩家所在维度
    "enforce": false,                // 是否启用"离开 host 就清理"；缺省 false
    "grace_ticks": 6000,             // 缺省 6000（5 分钟，本次由 1200 改）
    "warn_before_ticks": 600,        // 缺省 600（30 秒）；0 = 不提醒
    "warn_text": "…",
    "warn_key": "…"
  }
}
```

**四条补充**：

1. `enforce: false` 时 `host` **仍然生效** —— 它只决定"巡检去哪找"，不决定"必须待在里面"（这正是本次拆字段的目的）
2. 秒数占位符：`warn_text` / `warn_key` 里写 `%s` 就填**剩余秒数**，不写就是固定文案（现有的两条提醒就是这么工作的）
3. 内置默认键沿用 `beloong.npc.story.expiring` / `beloong.npc.story.outside_dimension` ⇒ **顺带解决 D18 那条瑕疵**（"龙宫"原本写死在语言文件里）
4. `lease.ticks = -1`（永久）⇒ 该剧情的**到期提醒自动跳过**（无意义）；若作者**显式**写了 `warn_before_ticks > 0` ⇒ 视为**逻辑矛盾 ⇒ 拒绝整文件**

## 四、数据流：时序与竞态

| 场景 | 结果 |
|---|---|
| 在线 + 到期 + 未完赛 | `timeout` ⇒ **删 + 撤**（现状不变） |
| 在线 + 到期 + 已通关 | `timeout` ⇒ 删、不撤（现状不变） |
| **离线 + 到期** | **只删** ⇒ 下次登录 ⇒ D21 ⇒ **撤** |
| 离线 + 未到期 | 不动（这正是要优化掉的那部分 tick） |
| **"删他分身的同一刻他登录"** | 两者都在**主线程** ⇒ 天然顺序化：要么登录时还在 ⇒ 完整判定清掉；要么已被离线清掉 ⇒ D21 撤 —— **两种顺序结果一致，无洞** |
| 迭代安全 | 先**快照 owner 集合**再遍历（删除会改实体列表） |
| 一个 owner 多只分身 | 离线路径对**每一只**各判租约，各自到期各自删 |
| 幂等 | 删掉后下一轮 `byOwner` 里就没有它 ⇒ 不会重复清理，日志只出一次 |

**性能账**：改前"到期的分身永不结算" ⇒ 每个弃坑玩家长期占一只 tick 的 Mob（无界）；
改后到期即删 ⇒ 上限 = **在线玩家数 + 最近一个租约内下线过的人数**（有界）；
且**没有到期物时零额外成本**（那一趟遍历本来就要做）。

**登录路径受两道既有保护**：① "搜索可信"闸门（必须扫到锚点才敢重置，上一轮 C2 修复）；
② **已通关者永不重置**（上一轮 C1 修复）—— 后者是"离线清理"能与 D21 安全共存的关键：
通关后被租约清掉分身的老玩家，登录后**不会**被打回起点，而且（`keep_after_finish=false` 时）会重新看到入口的公共锚点。

## 五、错误处理：报错不静默

**总原则**：凡是服务端查得到的，一律**加载期硬校验 ⇒ 拒绝整文件 + ERROR 点名到"哪个分组里的哪个键"**；绝不"WARN 一下按默认值继续跑"。

### A. 硬错误 ⇒ 拒绝整文件

| 类别 | 例子 | 备注 |
|---|---|---|
| 未知键（任意层） | 顶层写 `lifetime_ticks`（**旧版写法**） | ⭐ ERROR 附**迁移提示**：`'lifetime_ticks' 是旧版写法，现在应写成 'lease.ticks'` |
| 类型错 | `"ticks": "一小时"` | DFU 的报错也一并打出来 |
| 取值越界 | `ticks < -1` · `warn_before_ticks < 0` · `grace_ticks < 0` | |
| 逻辑矛盾 | `enforce: true` 却没 `host`；`ticks = -1` 却显式写了 `warn_before_ticks > 0` | 后者只在"显式写了非零值"时才判（缺省 600 与 `-1` 并存不算错） |
| `host` 维度不存在 | 查 `LEVEL_STEM`（加载期可得） | 本次新增的能力（D13） |
| `warn_text` 为空串 / `warn_key` 不是合法 id | 格式可查 | |
| 进度 id 不存在 | `start_advancement` / `end_advancement` | 加载期能查到就拒绝；若因 reload 顺序查不到，则**首次使用时打 ERROR**（不再只是 WARN）。理由：这两个 id 错了剧情根本不可能触发、撤回时也走不完父链 |

### B. 唯一物理上做不到硬报错的一条

**`warn_key` 指向的语言键是否存在** —— `lang` 是**客户端**资源，服务端拿不到，无法在加载期校验。
但它**不静默**：键不存在时玩家屏幕上会直接显示 `beloong.xxx.yyy` 原始键名，一眼可见。
（这也是为什么保留 `warn_text` 字面文案作为首选 —— 想绝对不出错就写字面文本。）

### C. 软着陆的唯一例外

**`cg` 名不存在 ⇒ 加载期 ERROR 但不拒绝**：ERROR 点名【哪个文件、哪条剧情、写的什么名字、当前已注册的 CG 名录】，剧情照常加载，只是不播登场 CG。这是 D12 的既定取舍（坏 CG 数据不该毁剧情）。

### D. 可观测性

- 离线清理的日志 reason = **`timeout_offline`**（与在线 `timeout` 区分）
- 未知字段的 ERROR **点名到具体键与所在分组**
- 软着陆的 `cg` 错误在加载期就报（不是等到玩家触发时才报）

## 六、迁移

| 文件 | 迁移后 |
|---|---|
| 模组自带 `data/beloong/beloong/npc_story/mo.json` | `lease{ ticks: 72000, keep_after_finish: **true** }`（保住短剧情的 D6）+ `dimension{ host: beloong:loong_palace, enforce: true }`（原本就开着）+ `grace_ticks` 走**新缺省 6000** |
| 整合包 `kubejs/data/beloong/beloong/npc_story/mo.json` | `lease{ ticks: 72000（显式写出便于阅读）, keep_after_finish: false }` + `dimension{ host: beloong:loong_palace, enforce: true, grace_ticks: 6000 }` |

**旧写法 → 新写法**（会被拒绝并提示）：

| 旧写法 | 新写法 |
|---|---|
| `lifetime_ticks` / `clear_on_logout` / `keep_after_finish` | `lease.ticks` / `lease.clear_on_logout` / `lease.keep_after_finish` |
| `required_dimension` | `dimension.host`（想启用清理再加 `dimension.enforce`） |
| `dimension_grace_ticks` | `dimension.grace_ticks` |

⚠️ **旧结构会被拒绝**（刻意：要么新的、要么不加载、要么报错，不留两种写法并存）⇒ **代码与两份数据必须同批完成**，否则中间态是"数据被拒 + 分身根本不生成"。
⚠️ 整合包现在的测试配置是"1 小时 + 宽限 10 秒" ⇒ 迁移后变成"1 小时 + 宽限 **5 分钟**"（更宽松）。

## 七、非目标

- **不**做离线撤进度（D1；那需要读存档或新持久状态）
- **不**把校验收紧推广到 `npc_dialogue` / `npc_route`（同一原则适用，但属另一批改动；本次只动 `npc_story`）
- **不**做跨维度传送（旧决定）
- **不**引入任何每玩家持久状态（沿用原设计的 D4）

## 八、风险

| 风险 | 应对 |
|---|---|
| 迁移破坏性 | 代码 + 两份数据**同批**；计划里把"改完立刻验证加载日志"列为必做步骤 |
| 无 `host` 的剧情 ⇒ 离线清理不生效 | 文档写明；加载期不报错（它是合法配置：只是退化） |
| `keep_after_finish: true` ⇒ 无离线清理 | D6 的刻意取舍；此类剧情的中途分身仍在**登录时**被清 |
| 常加载维度里"到期的分身"仍会 tick 到巡检那一刻（≤5 秒） | 可接受：巡检间隔可配 |
| 项目**没有测试套件** | 验证 = 编译 + 两套不变量 + 三探针 + 实机（离线清理需"常加载维度 + 玩家退出"才能观察） |
