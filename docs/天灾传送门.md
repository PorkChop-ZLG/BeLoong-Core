# 天灾传送门

## 概述

天灾传送门是化龙核心（BeLoong Core）模组添加的双向传送系统，连接任意维度和天灾维度（`beloong:disaster`）。设计模仿原版末地传送门和末地创世（End Remastered）模组：玩家使用 12 种不同的眼球物品填充 5×5 环形框架来激活传送门。

**核心特性：**

- 5×5 环形框架结构（12 个框架方块 + 3×3 传送门内部）
- 12 个可配置的眼球物品槽位，互不重复，消耗性嵌入
- 双向传送：下行（任意维度 → 天灾维度）1:1 坐标 + 自动生成返回传送门；上行（天灾维度 → 主世界）使用原版末地返回逻辑
- 13 种 BlockState 纹理变体（1 空 + 12 眼球），使用 `EnumProperty<EyeType>` 驱动
- 自定义传送门渲染器（原版末地星空着色器）
- 框架可挖掘（下界合金镐），破坏后传送门方块同步消失

## 核心类

### DisasterPortalFrame — 天灾传送门框架

**路径**：`block/DisasterPortalFrame.java`
**继承**：`Block implements EntityBlock`

5×5 环形结构中的框架方块。每个方块绑定一个 `DisasterPortalFrameEntity` 存储槽位编号。

**BlockState 属性**（3 个，共 2×4×13=104 种排列）：

| 属性 | 类型 | 值 |
|------|------|-----|
| `FACING` | `EnumProperty<Direction>` | `north`, `east`, `south`, `west` |
| `HAS_EYE` | `BooleanProperty` | `true`, `false` |
| `EYE_TYPE` | `EnumProperty<EyeType>` | `0` (空) 或 `1`~`12` (槽位) |

**传送门形状（5×5 环形）**：

```
    ?   v   v   v   ?      Row 0: 角落任意 + 3 框架朝北
    >   ?   ?   ?   <      Row 1: 框架朝西 + 3 空 + 框架朝东
    >   ?   ?   ?   <      Row 2: 同上
    >   ?   ?   ?   <      Row 3: 同上
    ?   ^   ^   ^   ?      Row 4: 角落任意 + 3 框架朝南
```

使用 `BlockPatternBuilder` 匹配。? 为任意方块，12 个符号位各自对应特定朝向的框架方块。

**关键方法**：

- `getCompletedPortalShape(boolean requireEyes)` — 构建匹配模式。`requireEyes=true` 时仅匹配 `EYE_TYPE != 0` 的框架（激活检测）；`false` 时匹配所有框架（去重检测）。
- `useItemOn()` — 眼球嵌入流程：查配置 → 去重 → 设 BlockState → 同步 BlockEntity → 激活检测。
- `isEyeAbsent()` — 遍历已搭建的 5×5，检查同槽位眼球是否已存在。
- `onRemove()` — 框架被破坏时扫描 7×7 水平范围，销毁所有传送门方块（产生破碎音效和粒子）。

**方块属性**：`strength(50, 1200)`, `requiresCorrectToolForDrops()`, 绿色地图色, 玻璃音效, 发光等级 1。

### DisasterPortalBlock — 天灾传送门方块

**路径**：`block/DisasterPortalBlock.java`
**继承**：`Block implements EntityBlock`

传送门激活时自动填充在 5×5 框架的中间 3×3 区域。玩家接触时触发双向传送。

**entityInside() 传送逻辑**：

```
当前维度 != "beloong:disaster"（下行）：
  1. 获取天灾维度 ServerLevel
  2. 保持 X/Z 坐标不变（1:1）
  3. 查询高度图获取安全落脚 Y
  4. player.teleportTo(targetLevel, x, topY+1, z)
  5. placeReturnStructure() 在目标坐标 + 配置偏移处生成结构模板

当前维度 == "beloong:disaster"（上行）：
  1. 获取玩家重生点（床/重生锚）
  2. 无重生点时回退到世界出生点
  3. player.teleportTo(overworld, respawnX+0.5, respawnY, respawnZ+0.5)
```

**placeReturnStructure()**：从 `data/beloong/structure/` 加载 `.nbt` 结构模板，使用 `StructureTemplate.placeInWorld()` 放置，位置由配置项 `structureOffsetX/Y/Z` 微调。

**方块属性**：`strength(-1, 3600000)`（不可破坏），`noLootTable()`, `noCollission()`, 发光等级 11, `RenderShape.INVISIBLE`。

### DisasterPortalFrameEntity — 框架 BlockEntity

**路径**：`block/DisasterPortalFrameEntity.java`

存储嵌入的眼球槽位编号。

| NBT 键 | 类型 | 含义 |
|--------|------|------|
| `eye_id` | String | 槽位编号 `"1"`~`"12"`，默认 `"0"` 表示空 |

提供 `saveAdditional/loadAdditional`（持久化）、`getUpdateTag/getUpdatePacket`（客户端同步）。

### DisasterPortalBlockEntity — 传送门 BlockEntity

**路径**：`block/DisasterPortalBlockEntity.java`

无数据存储。仅作为 `DisasterPortalRenderer` 的载体。`shouldRenderFace(Direction)` 仅对 Y 轴返回 `true`（和原版末地传送门一致，仅上下可见）。

### DisasterPortalRenderer — 传送门渲染器

**路径**：`client/DisasterPortalRenderer.java`（仅客户端）

原版 `TheEndPortalRenderer` 的完全重新实现。使用 `RenderType.endPortal()` 着色器渲染 6 面立方体，产生旋转星空隧道效果。每个面通过 `blockEntity.shouldRenderFace()` 判断是否绘制。

### EyeType — 眼球类型枚举

**路径**：`block/EyeType.java`
**实现**：`StringRepresentable`

| 枚举值 | 序列化名 | 槽位 |
|--------|---------|------|
| `EMPTY` | `"0"` | 空框架 |
| `SLOT_1` ~ `SLOT_12` | `"1"` ~ `"12"` | 对应配置 `eyeItems[0]` ~ `eyeItems[11]` |

槽位编号是从配置列表**位置索引 +1** 得出的。`fromKey("5")` 返回 `SLOT_5`。

### ModBlocks — 方块注册与工具方法

**路径**：`registry/ModBlocks.java`

提供 `getEyeSlot(ItemStack)` 静态方法：在 `Config.DisasterPortal.eyeItems` 列表中查找物品的完整 ID（如 `"cataclysm:mech_eye"`），返回其在列表中的位置 +1（即 1~12 的槽位编号）。未找到返回 0。

## 配置项

`Config.java` 服务端配置 `disaster_portal` 节：

| 配置键 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `eyeItems` | `List<String>` | 12 种眼球 ID | 列表第 N 项 → 槽位 N+1，须包含冒号 |
| `returnStructureTemplate` | `String` | `beloong:disaster/return_portal` | 返回传送门 .nbt 结构路径 |
| `teleportCooldownTicks` | `int` | 100 | 传送后冷却（ticks） |
| `structureOffsetX` | `int` | -2 | 结构放置 X 偏移（正=东，负=西） |
| `structureOffsetY` | `int` | 0 | 结构放置 Y 偏移（相对地表） |
| `structureOffsetZ` | `int` | -2 | 结构放置 Z 偏移（正=南，负=北） |

默认偏移 `(-2, 0, -2)` 使玩家站在 5×5 结构底部平台的正中央。

## BlockState 模型匹配

使用 **multipart** 格式（非 variants），原因：

- `HAS_EYE` 和 `EYE_TYPE` 是独立属性，Minecraft 会尝试所有 104 种排列
- multipart 中 `eye=false` 仅匹配面对朝向，无视 `eye_type` 值（自动处理 52 种"不可能"组合）
- `eye=true` + 特定 `eye_type` 匹配对应的眼球模型
- 任何未匹配的状态不渲染模型

## 数据流

### 激活流程

```
玩家右键框架
  → HAS_EYE 已为 true? → PASS
  → getEyeSlot(stack) → 查 eyeItems 配置列表
  → 未找到 (返回 0)? → PASS
  → isEyeAbsent(level, pos, eyeType) → 同槽位已存在? → 提示"已放置" → FAIL
  → setBlock: HAS_EYE=true, EYE_TYPE=对应值
  → BlockEntity.setEyeId(String.valueOf(slot))
  → stack.consume(1)
  → getCompletedPortalShape(true).find() → 12 帧全满?
      → 填充 3×3 DisasterPortalBlock
      → 播放激活特效 (1038)
  → CONSUME
```

## 设计决策

1. **EnumProperty<EyeType> 而非动态字符串**：BlockState 属性必须在编译期确定所有值，否则 BlockState JSON 无法匹配。选择 13 个固定槽位（1 空 + 12 眼球）。

2. **数字槽位而非语义化命名**：原始设计使用 `"ender_eye"`, `"mech_eye"` 等语义短键，但导致配置与硬编码 Map 绑定。改为数字槽位后，配置列表的任意物品 ID 都可使用，纹理由槽位编号决定。

3. **multipart 而非 variants**：variants 需要穷举所有排列（104 种），multipart 通过条件匹配自动忽略"不可能"状态。

4. **自定义渲染器而非继承 TheEndPortalBlock**：原版 `TheEndPortalRenderer` 在字节码级别硬转型 `TheEndPortalBlockEntity`，无法通过子类化复用，必须重新实现。

5. **结构模板偏移配置**：使用 `define()` 而非 `defineInRange()`，因为偏移值可能为负数。
