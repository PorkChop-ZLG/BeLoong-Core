## 三、试炼启动链

```
玩家右键雕刻家
  └ mobInteract（:764）canTradeWith（:773）→ openGUI（:738）
        · canTradeWith = !isTrading && health > 0 && !testing
  └ 交易界面里放入物品 → 客户端发 MessageSculptorTrade
        └ MessageSculptorTrade.handleServer（MessageSculptorTrade.java:21-39）
             ① sculptor.getCustomer() == player
             ② player.containerMenu instanceof ContainerSculptorTrade
             ③ !sculptor.checkTestObstructed()      ← 场地不得被方块挡住
             ④ sculptor.fulfillDesire(slot0)        ← 物品满足索要
             ⑤ trade.returnItems() + sculptor.setTestingPlayer(player)
  └ setTestingPlayer（:725-732）
        · 写 TESTING_PLAYER entityData
        · DataHandler → PlayerData.setTestingSculptor(this)
  └ RunTestGoal.canUse（:1705-1707）
        testingPlayer != null && isAlive() && !isRemoved()
  └ RunTestGoal.start（:1709-1713）
        testing = true；发 START_TEST
  └ StartTestAbility（:1793-1922）
        · tryAbility（:1811-1829）：从雕刻家向下 clip 12 格（MAX_RANGE_TO_GROUND=12）
              - Type.MISS ⇒ 不能开始
              - 命中面 != Direction.UP 时，额外要求命中点上方方块「不窒息且非空气」
        · start（:1832-1837）：清空 prevPlayerPosition / prevPlayerVelY
        · ACTIVE 段（:1876-1902）：
              建 EntityPillarSculptor（GeomancyTier.SMALL）于命中点，
              setDoRemoveTimer(false)，checkCanSpawn() 通过才 spawn
              placeStartingBoulders（:1839-1867）
  └ placeStartingBoulders
        · 随机数 numStartBoulders = rand.nextInt(2, 5) ⇒ **2~4 个**
        · 环绕柱子半径 3~6 格（`:1848`），随机角度偏移
        · 第 0 个 setMainPath()
        · sculptor.numLivePaths = numStartBoulders
```

**索要物品**：`whichItem` 默认 `ItemHandler.BLUFF_ROD`，`howMany` 默认 1
（`ConfigHandler.java:724-729`）。判定为 `canPayFor`：同物品且 **数量 ≥**（`:781-783`）。

**开局推动**：`StartTestAbility.tickUsing()` ACTIVE 段会把 5 格内的活体向外推开
（`:1906-1916`，力度 `min(1/d², 2.0)`）。

## 四、试炼场地几何

常量（`EntitySculptor.java:116-122`，`TEST_HEIGHT` 会被配置覆盖 `:211`）：

| 常量 | 默认 | 含义 |
|---|---|---|
| `TEST_HEIGHT` | 60（配置 `test_height`，1–500） | 试炼高度 = 柱子目标高度 |
| `TEST_RADIUS_BOTTOM` | 6 | 底部半径 |
| `TEST_RADIUS` | 12 | 最大半径 |
| `TEST_MAX_RADIUS_HEIGHT` | 20 | 半径达到最大值的高度 |
| `TEST_RADIUS_FALLOFF` | 5.0 | 半径随高度的幂次 |
| `HEAL_PAUSE` | 75 | 脱战回血延迟 |
| `DEFENSE_HEALTH_THRESHOLD` | 0.8 | 低于此血量才反击 |
| `testTimeLimit` | 400 秒 | `getMaxTestTime()` = `400 × 20` = **8000 tick**（`:919-921`） |

**半径函数**（`:667-670`）：

```java
testRadiusAtHeight(h) = TEST_RADIUS_BOTTOM + min(h / TEST_MAX_RADIUS_HEIGHT, 1)^TEST_RADIUS_FALLOFF
                        × (TEST_RADIUS − TEST_RADIUS_BOTTOM)
                      = 6 + min(h/20, 1)^5 × 6
```
⇒ 0 格处半径 **6**，≥20 格处半径 **12**（**收口漏斗**）。

**「在试炼区内」**（`isPlayerInTestZone` `:881-895`）：
- 水平 `distanceToSqr < TEST_RADIUS² + 9` = **153**（约 12.37 格）
- `yBase − 12 < y < yBase + 60 + 12`，其中 `yBase = pillar.getY()`，无柱时用雕刻家自身 Y

> 注：`isPlayerInTestZone` **只用于客户端表现**（粒子 / 方块标记 / 本地玩家判定），**不参与任何判负**。

## 五、场地障碍检测 `checkTestObstructed()`

**全量版**（`:482-494`）：
```
for i in 1..TEST_HEIGHT+3:            # 默认 63 层
    checkTestObstructedAtHeight(i)
    一旦 isTestObstructed ⇒ return true
```

**逐层版**（`:500-…`）：对某一层高度，在 `±TEST_RADIUS` 的方形内逐点扫描，
只取 `offset.lengthSquared() < testRadiusAtHeight(该层高度)²` 的点；
**任何「非空气且非 `Blocks.LIGHT`」的方块 ⇒ 判定受阻**。

**常态增量扫描**（`tick()` `:437-446`）：当 `!testing && !isFighting()` 时，
每 tick **只扫一层**，`obstructionTestHeight` 递增并取模 `TEST_HEIGHT+3`；
一轮走完（回到 0）时才把 `isTestObstructedSoFar` 落成 `isTestObstructed`
⇒ 语义是「**整根柱子体积都被扫过且无阻碍**」。

**客户端副作用**（`:514-531`）：若本机玩家在试炼区内且该方块有暴露面，
则 `sculptorMarkBlock` 标记 + 生成 `RING2` 粒子（`AdvancedParticleBase.spawnAlwaysVisibleParticle`）。

**作用**：`MessageSculptorTrade` 在放行前**同步全量扫一次**，被挡就**不让开始试炼**
⇒ **不能在柱子将要生成的位置预先搭方块**。

## 六、反作弊系统（**共两套，互相独立**）

> ⚠️ 本节是本文档的重点。**两套机制的代码位置、触发方式、判定内容都不同**，
> 只改其中一套不会让另一套失效。

### 6.1 第一套：`EntitySculptor#checkIfPlayerCheats()` —— 逐 tick 物理检测

- **定义**：`EntitySculptor.java:603-653`
- **唯一调用点**：`RunTestGoal.tick()` `:1721-1725`，前置条件
  `sculptor.testing && activeAbility != FAIL_TEST && activeAbility != PASS_TEST`
  ⇒ **不在 `EntitySculptor.tick()` 里**
- **外层门**（`:604-605`）：`testingPlayer != null && isTesting() && !testingPlayer.isCreative()`
  ⇒ **创造模式玩家完全免疫**

**六条规则**（else-if 链，命中即 `playerCheated()`）：

| # | 检查 | 阈值 | 行 |
|---|---|---|---|
| 1 | 水平距离 | `> TEST_RADIUS + 4`（=**16**） | `:606-608` |
| 2 | 低于柱底 | `y < pillar.getY() − 10` | `:609-610` |
| 3 | **飞行** | `getAbilities().flying` | `:611-612` |
| 4 | **水中且未落地** | `isInWater() && !onGround()` | `:613-614` |
| 5 | **持续向上加速** | 未落地时逐 tick 比较 `deltaMovement.y`：`Δ ≥ 0` 则 `ticksAcceleratingUpward++`，`Δ < 0` 则 `--`；**`> 5` 判负** | `:616-630` |
| 6 | **传送 / 位置跳变** | `position()` 与「上一 tick 位置 + 当前 `deltaMovement`」的距离 `> 3.0` | `:638-649` |

**结构细节**：
- 规则 1–5 是 else-if 链 ⇒ **每 tick 最多判一条**。
- 规则 5、6 位于**最后一个 `else` 分支**内（`:615-650`）：
  - 规则 5 判负时 **`return`**（不刷新 `prevPlayerVelY`）
  - 规则 6 判负时 **`return`**（不刷新 `prevPlayerPosition`）
  - `prevPlayerPosition` **只在进入该 else 分支时**才更新（`:648`）
    ⇒ 玩家一旦被判飞行/水中，那一 tick 的基准位置**不刷新**
- 落地时重置（`:633-636`）：`ticksAcceleratingUpward = 0`、`prevPlayerVelY = empty`

**状态字段**（`:188-190`，**均不写入 NBT**）：

| 字段 | 全部引用点 |
|---|---|
| `prevPlayerVelY` | 仅 `:618/619/632/635` + 重置点 `:1720`、`:1836` |
| `prevPlayerPosition` | 仅 `:640/641/648` + 重置点 `:1719`、`:1835` |
| `ticksAcceleratingUpward` | 仅 `:621/622/623/626/634` |

⇒ **完全自包含**：除本方法外无任何读方。

**判负动作** `playerCheated()`（`:655-659`）：
```java
if (isTesting() && testingPlayer != null
    && activeAbilityType != FAIL_TEST && activeAbilityType != PASS_TEST) {
    sendAbilityMessage(FAIL_TEST);
}
```

### 6.2 第二套：`ServerEventHandler#cheatSculptor(Player)` —— 事件驱动的行为检测

- **定义**：`ServerEventHandler.java:956-966`
- **逻辑**：以**玩家**为中心，取一个膨胀盒
  （水平 `±(TEST_RADIUS + 3)`、垂直 `±TEST_HEIGHT`），
  找出盒内**所有**满足 `isTesting() && activeAbility != PASS_TEST && activeAbility != FAIL_TEST`
  的雕刻家，对**每一个**调 `playerCheated()`
  ⇒ **不检查这个玩家是不是该雕刻家的 testingPlayer**

**三个调用点（全部在 `ServerEventHandler`）**：

| # | 事件处理器 | 触发条件 | 行 |
|---|---|---|---|
| 1 | `onPlaceBlock`（`EntityPlaceEvent`） | 玩家**放置任意方块** | `:440` |
| 2 | `onFillBucket`（`RightClickItem`） | 手持物是 **`Items.WATER_BUCKET`** | `:475` |
| 3 | `onBreakBlock`（`BreakEvent`） | 玩家**破坏任意方块** | `:486` |

（前两者还各有其他副作用：放火/TNT/重生锚/发射器/仙人掌会 `aggroUmvuthana`；
倒岩浆桶也会 `aggroUmvuthana`——与雕刻家无关。）

### 6.3 两套机制的对照

| 维度 | 第一套 `checkIfPlayerCheats` | 第二套 `cheatSculptor` |
|---|---|---|
| 宿主 | `EntitySculptor` | `ServerEventHandler` |
| 触发 | 每 tick（由 `RunTestGoal` 驱动） | **玩家行为事件**（放/破方块、倒水桶） |
| 检测对象 | 雕刻家的 `testingPlayer` | **盒子范围内的任意 testing 雕刻家** |

| 创造模式豁免 | ✅ 有（`:605`） | ❌ **无** |
| 状态依赖 | 三个自包含字段 | 无状态 |
| 关掉第一套后 | — | **仍然完全生效** |

## 八、通关路径（**唯一方式**）

`mobInteract`（`:754-771`）—— **在柱顶右键雕刻家**，需同时满足 5 个条件：

| # | 条件 | 行 |
|---|---|---|
| 1 | `isTesting()` | `:755` |
| 2 | `getPillar() != null` | `:755` |
| 3 | **`!pillar.isRising()`**（柱子必须已停止上升） | `:755` |
| 4 | `player == testingPlayer` | `:756` |
| 5 | `activeAbilityType != FAIL_TEST` **且** `player.distanceToSqr(sculptor) <= 20.0`（约 **4.47** 格） | `:756` |

通关瞬间触发成就 `SculptorChallengeTrigger`（`:758-760`）。

**关键联动 —— 雕刻家会被抬到柱顶**：
`EntityPillar.EntityPillarSculptor.stopRising()`（`EntityPillar.java:350-356`）
```java
super.stopRising();
if (getCaster() instanceof EntitySculptor sculptor) {
    sculptor.setPos(this.position().add(0.0, this.getHeight(), 0.0));
}
```
⇒ 所以「爬到柱顶 → 靠近雕刻家 → 右键」才是正解。

**柱子（`EntityPillarSculptor`）的升降条件**（`EntityPillar.java:328-348`、`:311-357`）：

| 条件 | 动作 |
|---|---|
| 雕刻家头顶上方（`blockPosition().above(bbHeight+1)`）有 `blocksMotion()` 方块 | `stopRising()` |
| **`!isFighting() && !isTesting()`**（服务器侧） | `startFalling()` |
| `getHeight() >= getDesiredHeight()`（= `TEST_HEIGHT`）且正在上升 | `stopRising()` |
| 构造时 | `setDeathTime(300)`；`getDesiredHeight()` 返回 `TEST_HEIGHT` |

**注意**：通关只要求「柱子**不在上升**」，**不要求** `getHeight() >= TEST_HEIGHT`。

## 十二、本项目当前 mixin 与上述机制的差异
